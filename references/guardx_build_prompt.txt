============================================================
1. PROJECT DEFINITION
============================================================

GuardX is a modular AI security/guardrail middleware and API service that sits between an AI application/agent and an LLM or external tool.

Its purpose is to inspect:

1. User prompts / AI inputs
2. LLM outputs
3. AI-agent/tool actions

before they are delivered to users or executed.

GuardX uses multiple specialized safety agents:

1. Security Agent
2. Privacy Agent
3. Content Agent
4. Policy Agent

Their results are normalized and passed to a Risk Scoring / Ensemble Engine.

An Arbiter then makes the final decision:

- ALLOW
- MODIFY
- BLOCK
- HUMAN_REVIEW

The system must provide explainable decisions, risk scores, detected categories, agent-level results, and audit logs.

The architecture should be designed so GuardX can eventually become a SaaS/API product, while the current implementation remains realistic for a final-year major project.

============================================================

GuardX is NOT primarily:

- a chatbot

GuardX is:

6. INPUT / OUTPUT / ACTION PIPELINES
============================================================

GuardX must support three conceptual evaluation types.

A. INPUT CHECK

Purpose:
Protect the LLM from malicious or sensitive user input.

Flow:

User
 -> GuardX
 -> Security/Privacy/Policy/Content checks
 -> Decision
 -> If allowed/sanitized, send to LLM

CRITICAL PRIVACY REQUIREMENT:

Raw PII must NOT be sent to an external LLM merely to determine whether it is PII.

Initial PII detection must happen locally using deterministic/NLP mechanisms.

If PII is detected:

- BLOCK
or
- MODIFY/REDACT
depending on policy.

Only the sanitized prompt should be allowed to continue to an external LLM.

Example:

Input:
"My email is john@example.com and my account number is 123456789."

Sanitized:
"My email is [EMAIL_REDACTED] and my account number is [ACCOUNT_NUMBER_REDACTED]."

B. OUTPUT CHECK

Flow:

LLM
 -> GuardX
 -> evaluate output
 -> ALLOW / MODIFY / BLOCK
 -> user

C. AI AGENT ACTION CHECK

Example:

Agent proposes:

{
  "tool": "send_email",
  "parameters": {
      "recipient": "...",
      "body": "..."
  }
}

GuardX evaluates the proposed action before execution.

This is especially important for:

- sensitive data exposure
- unauthorized operations
- dangerous tool calls
- policy violations
- suspicious actions
